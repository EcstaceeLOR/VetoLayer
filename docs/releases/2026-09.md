# VetoLayer 2026.09 release notes

Released: **2026-09-25**

This release documents the finished-product hardening delivered across Issues #54–#65.

## Product scope and administration

- Durable workspaces, projects, environments, membership roles, invitations, and server-side RBAC.
- First-class Settings with stale-write protection, credential masking, destructive-action confirmation, retention controls, and append-only security audit retention.

## Integrations and developer platform

- Production GitHub App installation/callback/webhook flow with signature verification and replay protection.
- Developer Console with project/environment-scoped API keys, live request tester, signed webhook endpoints, secret rotation, retries, and delivery history.
- Stable `/api/v1/evaluate` plus decision read endpoints and `@vetolayer/sdk` evaluate-before-execute helpers.

## Governance and operations

- Versioned Policy Studio with drafts, templates, simulation, diffs, activation, immutable published versions, and rollback by re-activation.
- Operational Human Review with assignment, evidence requests, provenance, comments, rationale, concurrency conflicts, real orchestrator re-evaluation, and receipt lineage.
- Decision Explorer and Receipt Center with scalable filters/search, pagination, saved views, integrity verification, compare, lineage, and secure exports.
- In-product/email notifications plus durable outbound webhook delivery and retry semantics.
- Append-only activity/security audit center and operational analytics/reporting.

## Documentation

- New in-product Documentation center under `/dashboard/docs`.
- Stable contextual help routes for Developer, Integrations, Policies, and Reviews.
- Current API authentication/error reference and webhook signature/event reference.
- Compile-checked SDK quickstart source at `packages/sdk/src/docs-quickstart.ts`.
- Release smoke now requires the shipped docs surface and canonical documentation artifacts.

## Breaking/compatibility guidance

- Developer API scope comes from the project/environment API key. Do not use obsolete global workspace headers.
- GitHub integrations use the installed GitHub App. Do not rely on personal GitHub access tokens.
- Active managed Policy Studio versions are authoritative. Request-supplied policy definitions are only a migration fallback when no managed policy is active in the scope.
